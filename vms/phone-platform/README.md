# Switchboard phone platform

Adds the dashboard and authenticated API to the existing phone VM **233** at
**http://192.168.0.233:8088**. This module creates no VM and does not restart
Asterisk, Home Assistant voice, or the Codex phone bridge.

The service runs as `codex-phone`, which lets it access the private phone control
socket using the bridge's existing same-user authorization. State and credentials
live under `/var/lib/codex-phone/switchboard`, with mode 0700 directories and 0600
credential files. Public application releases live under `/opt/phone-platform`.
The independent platform venv reuses existing pinned voice packages through a
`.pth` file; new server dependencies are installed only in the platform venv.

## Deploy

Set `phone-platform:enabled=true` and an encrypted `phone-platform:adminToken`
(a random URL-safe value of at least 40 characters), plus a different encrypted
`phone-platform:phoneToken` for read-only handset directories. The existing encrypted
`huddle-phone:operatorSecret` supplies the Huddle adapter's credential. No keys
belong in the public source snapshot.

```bash
python3 vms/phone-platform/sync-source.py /home/raygen/Projects/cisco-phone-shenanigans/phone-platform
pnpm exec tsc --noEmit
env -u SSH_AUTH_SOCK pulumi preview \
  --target 'urn:pulumi:homelab::pulumi-homelab::command:remote:Command::phone-platform-stage' \
  --target 'urn:pulumi:homelab::pulumi-homelab::command:remote:CopyToRemote::phone-platform-source' \
  --target 'urn:pulumi:homelab::pulumi-homelab::command:remote:Command::phone-platform-setup'
```

Review the preview before running the same targets with `pulumi up`. Only one
stack update can run at a time. A platform update restarts only this new API.
The installed `assert-idle.py` helper checks live Asterisk calls, Huddle call
state and running/queued Codex jobs immediately before service restarts. A busy
phone causes the deployment to stop for a later retry; it is never hung up.
Speech routing should be activated in the phone-voice service units only after
the new service's health, authentication, and local speech tests pass.

For initial integration, refresh all three public snapshots first:

```bash
python3 vms/phone-platform/sync-source.py /home/raygen/Projects/cisco-phone-shenanigans/phone-platform
python3 vms/huddle-phone/sync-project.py /home/raygen/Projects/cisco-phone-shenanigans
python3 vms/phone-voice/sync-source.py /home/raygen/Projects/cisco-phone-shenanigans
pnpm exec tsc --noEmit
```

Deploy in phases with `bash vms/phone-platform/pulumi-service.sh PHASE preview`
then the same command with `up`, reviewing every phase before deployment:

1. `platform`: creates the API, private state and directory mount source. Test
   authentication, local speech and session listing before proceeding.
2. `huddle`: updates the PBX, TFTP and Huddle application release. This recreates
   containers because their source bind mounts point at a new release; wait for
   current calls and huddles to finish. No VM replacement or volume deletion is
   involved. It activates the shared operator credential and Asterisk includes.
   Its completion hook reapplies the private directory URL automatically after
   selecting the new active release.
3. `voice`: installs the shared API client source for Codex and Home Assistant.
   The voice provisioner restarts both voice services; wait for calls and active
   agent tasks to finish. Then activate the drop-ins below and validate calls.

The helper selects only source, staging and application provisioning commands.
It does not select the VM, host preparation, DHCP, or unrelated stack changes.
If application code changes during initial validation, refresh its snapshot and
review a new preview before deploying that phase again.

Once the updated phone-voice source is deployed and existing calls/tasks are
idle, install `source/deploy/codex-phone-platform.conf` as
`/etc/systemd/system/codex-phone-bridge.service.d/phone-platform.conf`, and
`source/deploy/home-assistant-platform.conf` as the matching drop-in for
`home-assistant-phone.service`. Reload systemd and restart those two services
to activate central speech routing. The platform provisioner intentionally
does not install these drop-ins or restart voice services.

The project Compose file mounts the persistent `switchboard/asterisk` directory
into Asterisk read-only. Its `routes.conf` is generated by the platform and
included by `sccp-internal`. Alias updates need only a dialplan reload after the
one-time PBX container update that adds this mount. Fixed 555, 611 and 0 entries
remain in the versioned dialplan. Directory `_88XXXX` entries carry their
contact reference in the `d100XXXX` prefix of the operator's AudioSocket UUID.
After the directory mount exists, install `phone-platform-routing.conf` as
`/etc/systemd/system/phone-platform.service.d/routing.conf` and restart only the
platform service to enable automatic dialplan reloads from dashboard changes.

The Codex speech drop-in also puts `/opt/phone-platform/current/bin` on PATH,
so the reusable operator can invoke the bundled `switchboard` client. Native
Codex authentication and saved sessions remain owned by the existing bridge.

On the VM:

```bash
systemctl status phone-platform
journalctl -u phone-platform -f
```

The dashboard and admin API are LAN-only. This module registers only
`wss://speech.raygen.dev/speech-engine/upstream` with the existing homelab
Traefik/Cloudflare tunnel. Its router requires the exact path, a GET WebSocket
upgrade and the tunnel's source address. Switchboard then verifies the
ElevenLabs JWT before accepting the connection. Other paths and methods on this
dedicated hostname use `noop@internal`, including the otherwise shared Authentik
outpost path. The provider router disables access logs and tracing. Existing
wildcard DNS/TLS is reused; this module creates no DNS record or tunnel.

Include these additional resources when reviewing and deploying the upstream
ingress along with the platform release:

```text
urn:pulumi:homelab::pulumi-homelab::consul:index/node:Node::phone-platform-speech-engine-node
urn:pulumi:homelab::pulumi-homelab::consul:index/service:Service::phone-platform-speech-engine-service
```

Before activating cloud phone audio, verify that an unauthorized WebSocket
upgrade is rejected and that `/`, `/api/v1/settings` and
`/outpost.goauthentik.io/` do not reach Switchboard on this hostname. Provisioning
and the AudioSocket listener remain separate opt-in steps described in the
platform source's `SPEECH-ENGINE.md`.

The provisioner writes the Cisco handset's `directoryURL` only into the active
remote TFTP configuration. It uses the separate directory token, never the admin
token. Later Huddle deployments automatically reapply this private URL after
selecting their new TFTP release. For manual recovery, run
`python3 /opt/phone-platform/current/deploy/configure-phone.py` on the VM.
The phone fetches its changed configuration during its next normal restart.
