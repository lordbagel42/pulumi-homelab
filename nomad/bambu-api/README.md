# bambu-api on Nomad

The hosted [bambu-rea](https://github.com/lordbagel42/bambu-rea) API server at
`https://bambuapi.raygen.dev`: one allocation on the homelab Nomad client,
VM230 (`192.168.0.230`). It stores each signed-in account's Bambu session and
API keys in SQLite.

Traffic follows the homelab tunnel through cloudflared (`192.168.0.204`) and
Traefik (`192.168.0.203`). The proxied wildcard `*.raygen.dev` already points at
the tunnel, so the Consul tags in the job are the whole route. The router
accepts only the tunnel host, and `/v1/auth/` is rate limited per
`CF-Connecting-IP` because those routes call Bambu for anonymous callers.

## Image

There is no registry. Build a revision-tagged image from the bambu-rea checkout
and load it on VM230, then set `bambu-api:image` to that tag:

```sh
sha=$(git rev-parse --short HEAD)
docker build --build-arg VERSION="$sha" -t "bambu-api:$sha" .
docker save "bambu-api:$sha" | ssh root@192.168.0.230 docker load
```

For a full 40-character commit tag in `bambu-api:image`, the existing Deploy
workflow also accepts `bambu_api_only=true` on manual dispatch. It builds that
exact public source revision, loads and verifies the image on VM230 using the
ESC SSH identity and configured host key, previews only the existing Bambu job,
rejects other updates/replacements, applies the saved plan through Pulumi, and
requires a refreshed no-change preview afterward. It never runs `nomad job run`
outside Pulumi or rotates the stored data key. Keep the image config change in
the owning source branch; do not leave main pointing at a superseded image.

When using this scoped path, validate the source branch first, then preserve
`[skip ci]` in the final commit landing on main so the push does not also launch
the unrelated full-stack deployment. Manually dispatch Deploy at that exact main
revision with `bambu_api_only=true`. A workflow-dispatch run is not suppressed by
the commit marker. The final targeted no-change preview proves the Bambu job's
convergence only, not whole-stack convergence.

## Configuration

| Pulumi key             | Purpose                                                  |
| ---------------------- | -------------------------------------------------------- |
| `bambu-api:enabled`    | Register storage and, when an image is set, the job.     |
| `bambu-api:sshHostKey` | VM230's verified SSH host public key.                    |
| `bambu-api:image`      | Revision tag; `:latest` and untagged images are refused. |

The only secret is `BAMBU_API_DATA_KEY` in Infisical (`prod`, `/bambu-api`),
generated by `managedSecret` on first deploy. It encrypts the stored Bambu
tokens; **never rotate or delete it**, or every stored session becomes
unreadable and all users must sign in again. It reaches the container as
`BAMBU_DATA_KEY` in a dotenv file loaded through `BAMBU_ENV_FILE`.

| Host path on VM230                  | Container path               | Ownership and mode                    |
| ----------------------------------- | ---------------------------- | ------------------------------------- |
| `/opt/nomad/volumes/bambu_api_data` | `/data`                      | UID/GID 1000, `0700`                  |
| `/etc/bambu-api/bambu-api.env`      | `/run/secrets/bambu-api.env` | UID/GID 1000, `0400`; read-only mount |

The database is `/data/bambu-api.sqlite`. The container runs as 1000:1000 with
a read-only root filesystem, all capabilities dropped and no-new-privileges.
Host storage is retained when the resources are removed. Keep one replica: the
database has a single writer.

## Deployment

Target these resources when other homelab work is in progress:

```text
urn:pulumi:homelab::pulumi-homelab::command:remote:Command::bambu-api-storage
urn:pulumi:homelab::pulumi-homelab::command:remote:Command::bambu-api-environment
urn:pulumi:homelab::pulumi-homelab::command:local:Command::infisical-secret-BAMBU_API_DATA_KEY
urn:pulumi:homelab::pulumi-homelab::nomad:index/job:Job::bambu-api
```

Checks after a deploy: `/v1/healthz` returns `{"ok":true}`, `/docs` and
`/openapi.json` load, `/login` renders, and `/mcp` without a key returns `401`.
